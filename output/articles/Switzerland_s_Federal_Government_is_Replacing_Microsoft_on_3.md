# Switzerland's Federal Government is Replacing Microsoft on 3,000 Computers

# 为什么你想换掉 Microsoft 365却卡在“找不到合适的免费工具”？——瑞士政府用 openDesk 给你答案

很多人想把公司里的 Microsoft 365 换成免费或开源的方案，却总是找不到“一站式”工具，结果试了半天要么功能不全，要么迁移成本高，最后只能继续买贵价授权。其实，瑞士联邦政府已经在 3 000 台电脑上跑起了完整的替代方案，你完全可以照搬他们的思路。

## 为什么你做不成？卡在哪儿
- **只看单个工具**：很多人只挑了开源的文字处理或邮件客户端，结果发现缺少协同、日历、视频会议等完整套件，导致工作流被打断。  
- **缺少并行运行的策略**：直接全盘切换会导致业务中断，很多组织因此止步不前。  
- **没有官方验证的案例**：没有大规模、真实环境的成功案例，大家对风险感到不安。  

瑞士政府正是因为这些痛点，先做了 172 人的 PoC（“PoC BOSS”），确认了核心办公任务（文档处理、邮件）可以顺利使用 openDesk，才敢投入 9 百万瑞士法郎，启动 3 000 台电脑的试点。

## 具体怎么干
下面把瑞士政府的做法拆解成可操作的步骤，普通企业完全可以照搬：

1. **选定完整的开源套件**  
   - **工具名称**：`openDesk`（德国开源协作平台），包括文档编辑、邮件、日历、文件共享等。  
   - **获取方式**：直接访问 https://www.opendesk.eu/ 下载或使用官方提供的 Docker 镜像（原文未提及具体部署方式，按官方文档操作即可）。

2. **先做小范围 PoC**  
   - **规模**：挑选 150‑200 名员工（原文 PoC 为 172 人），让他们在真实工作中使用 openDesk。  
   - **评估维度**：文档处理、邮件收发、日历安排、文件共享的使用体验；对比现有 Microsoft 365 的功能缺口。  
   - **时长**：建议 4‑6 周，让用户有足够时间发现问题（原文未给出具体时长，按常规 PoC 设定）。

3. **并行运行，避免业务中断**  
   - 在 PoC 成功后，正式部署时保持 Microsoft 365 与 openDesk 同时运行，逐步把部门或项目迁移过去。  
   - 这样可以在出现兼容性或功能缺失时，立刻切回 Microsoft 365，确保业务不受影响（原文已说明试点阶段是并行运行）。

4. **预算与资源规划**  
   - 瑞士政府为 3 000 台电脑的迁移投入 **CHF 9 百万**（约合 1 百万美元），主要用于培训、迁移工具开发和技术支持。普通企业可以按比例（比如 10 %）预留预算，用于内部培训和外部顾问费用。

5. **监控与反馈**  
   - 在并行运行期间，收集用户反馈，记录哪些功能仍需改进（原文提到大规模视频会议仍有技术限制），并与 openDesk 社区沟通，推动功能完善。

## 避坑指南
| 常见错误 | 解决办法 |
|----------|----------|
| 只迁移文档/邮件，忽视日历、会议等协同功能 | 选用 **完整套件**（如 openDesk），确保所有核心模块都已部署。 |
| 直接全盘切换，导致业务中断 | 采用 **并行运行**，逐步迁移，确保出现问题时可回滚。 |
| PoC 规模太小，结果不具代表性 | 至少 **150‑200 人**的真实业务场景，才能发现大多数痛点。 |
| 忽视培训，用户不熟悉新系统 | 在 PoC 阶段就安排 **培训和文档**，让用户提前上手。 |
| 对视频会议等高负载场景缺乏评估 | 在 PoC 中专门测试 **大规模视频会议**，并准备备用方案（如使用开源 Jitsi）。 |

## 普通人能抄什么
1. **立即下载并部署 openDesk**：访问官方站点，按照文档在一台测试机器上跑起来，先熟悉界面和基本功能。
